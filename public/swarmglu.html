SwarmGlu Consensus & Swarm Glue

The liaison, consensus, and routing layer of the Tree4Five Tools ecosystem. Binds heterogeneous devices (Linux/Windows PCs, Android phones and tablets) into a self-organizing, self-healing AI swarm over local Wi-Fi with no Internet and no central server.

how_to_reg Zero-SPOF Lease Election

Eliminates single points of failure across dynamic classroom environments:

  • Lease-Based Heartbeats: Nodes emit heartbeats every 3 seconds. 6 seconds of leader silence deterministically triggers an election.
  • Deterministic Ordering: Lowest IPv4 wins, tied by lexicographical node ID. Rank-proportional proclamation delay prevents split-brain elections.
  • Rapid Failover: Measured real-world failover between 2 and 8 seconds on physical fleets without dropping active student queries.

lock_clock Immutable SHA-256 Audit Chain

Every swarm interaction is sealed in a tamper-evident audit journal:

  • Cryptographic Sealing: hash = sha256(canonical(event) + prev_hash + request_time) with sequence anti-gap verification.
  • Torn-Tail Auto-Repair: If an Android node process is killed during a disk write, verify_chain() repairs the tail and logs chain_tail_repaired.
  • Full Historical Replay: Audits student questions, election transitions, knowledge pool admissions, and inter-swarm relays.

security Hybrid Post-Quantum Cryptography

Secures edge intelligence against current and future quantum decryption threats:

  • ML-KEM-768 + ECDSA P-256: Dual post-quantum key exchange via /secure/handshake establishing HKDF-SHA256 session keys.
  • AES-256-GCM RPC: Authenticated symmetric encryption on all node-to-node communication.
  • Decentralized Whitelist Re-Signing: Weighted lottery (node uptime × request count) with signed 1/8 consensus quorum.

verified OSP v0.6 Firewall & RAG Pool

Enforces factual integrity before shared knowledge ingestion:

  • Groundedness Entailment: Scores AI answers with metric $g \ge 0.30$. Answers passing the firewall are stamped VERIFIED.
  • Shared Knowledge Base: Verified answers automatically enter the replicated RAG pool, synchronized across all devices via Last-Write-Wins (LWW).
  • Student Delivery: Unverified answers are flagged and returned to the student but excluded from the collective memory.

wifi_tethering Hotspot Range Extension & Relay

Overcomes physical school Wi-Fi dead-zones and network constraints:

  • LocalOnlyHotspot: A single tap on an Android tablet launches a local hotspot, turning the device into an autonomous swarm router.
  • Secure Relay: Proxies requests to the school server via POST /relay, restricted to private IP destinations and sealed in audit logs.
  • Inter-Swarm Gateway: Ambassador nodes synchronize state digests (/gateway/sync) across different classrooms with loop guards.

smartphone Native Android Application (8.8 MB)

Lightweight, battery-efficient standalone Android implementation:

  • Pure Kotlin Core: Standalone NanoHTTPD microserver; Chaquopy/Python dependency removed to reduce APK size from 62 MB to 8.8 MB.
  • Native BouncyCastle & java.security: Performs post-quantum ML-KEM-768 and ECDSA handshakes directly on Android hardware.
  • Three Core Screens: Real-time swarm dashboard, student question terminal with OSP badge, and audit chain integrity verifier.

code Quickstart: Run a SwarmGlu Node

SwarmGlu requires zero third-party pip dependencies on Python 3.8+ (Pure Standard Library):

# 1. Clone the repository
git clone https://github.com/wwebtvmedia/swarmglu.git
cd swarmglu

# 2. Start the classroom server node (bridges local Ollama GGUF backend)
python3 cli.py serve --node-id pc-prof --port 7001 --mode full \
    --gguf-url http://127.0.0.1:11434 --gguf-models fastmodel:latest \
    --api-flavor ollama-chat --advertise-ip 192.168.1.10

# 3. Verify audit chain integrity
python3 cli.py audit

# 4. Inquire the swarm from any terminal or student device
python3 cli.py ask "Explique la photosynthèse" --node http://192.168.1.10:7001
